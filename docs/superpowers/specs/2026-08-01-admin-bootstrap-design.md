# 管理员环境变量引导设计

## 目标

允许部署者在 `.env.production` 中填写一次性的管理员引导账号和密码。生产栈首次启动时自动创建管理员；数据库中已有管理员时跳过，不覆盖账号、密码或启用状态。

## 配置

新增两个可选变量：

```dotenv
ADMIN_BOOTSTRAP_USERNAME=admin
ADMIN_BOOTSTRAP_PASSWORD=至少8个字符的高强度密码
```

- 两项都为空时关闭自动引导，启动正常继续。
- 只填写其中一项时视为配置错误，生产栈停止在引导阶段。
- 两项都填写时沿用现有管理员登录账号和密码校验规则。
- 日志只输出创建、跳过或关闭状态，绝不输出密码。

## 架构

在数据库迁移之后、API 启动之前增加一次性的 Compose `bootstrap` 服务。该服务调用独立的管理员引导模块，因此业务规则可通过 API 工作区测试直接验证，而不依赖 shell 或 Docker。

执行顺序为：

1. PostgreSQL 健康。
2. `migrate` 完成 Prisma 迁移。
3. `bootstrap` 读取管理员引导变量并执行幂等初始化。
4. `api` 仅在 `bootstrap` 成功退出后启动。

## 数据规则

- 数据库中没有管理员时，创建配置指定的管理员并使用 Argon2 保存密码哈希。
- 数据库中已有任意管理员时返回跳过状态，不创建第二个管理员。
- 自动引导不会重置忘记的密码；密码变更继续作为独立管理功能处理。
- 创建成功后可从 `.env.production` 删除或清空这两个变量，后续重启不会影响已创建管理员。

## 验证

- 自动测试覆盖关闭、缺少单项配置、首次创建和已有管理员跳过。
- 全量发布检查覆盖类型检查、API 测试、生产构建、Compose 启动和健康检查。
