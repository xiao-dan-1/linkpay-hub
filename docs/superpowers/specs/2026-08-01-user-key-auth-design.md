# 用户密钥登录与管理员密钥管理设计

**状态：** 已确认设计方向，待实施
**适用项目：** 支付链接提交与工作室处理系统

## 1. 目标

将用户身份认证从“账号 + 密码”改为单一访问密钥。管理员负责创建密钥并可填写备注；密钥可重复登录，直到管理员停用。现有亮色视觉体系、用户工作台、工作室队列和管理员整体布局保持不变。

## 2. 用户流程

- 用户登录页只保留一个“访问密钥”输入框。
- 用户输入管理员发放的密钥后进入 `/user/workbench`。
- 密钥可在不同时间重复使用，不是一次性验证码。
- 用户会话仍使用服务端 HttpOnly Cookie，地址栏和浏览器存储不保存密钥。
- 停用密钥后，所有现有用户会话立即失效，历史任务继续保留。
- 用户注册页、账号密码登录和注册链接不再作为产品入口。

## 3. 管理员流程

管理员侧现有“用户管理”改为“密钥管理”：

- 点击“创建密钥”打开创建对话框。
- 可填写最多 200 个字符的备注，备注为空也可创建。
- 创建成功后完整密钥只显示一次，并提供复制按钮和明确的一次性保存提示。
- 列表展示掩码密钥、备注、启用状态、创建时间、最近使用时间和任务数量。
- 可按备注或掩码密钥搜索。
- 可停用或重新启用密钥；停用操作继续二次确认。
- 列表和后续 API 永不再次返回完整密钥。

## 4. 密钥规则

- 格式：`USR-XXXX-XXXX-XXXX-XXXX`。
- 字符集使用不易混淆的 Base32 大写字符，提供约 80 位随机熵。
- 服务端使用密码学安全随机数生成密钥。
- 数据库只保存 SHA-256 哈希、显示前缀和末四位，不保存完整密钥。
- 登录接口继续使用限流、CSRF、来源校验和统一错误信息。
- 创建、登录、停用和启用操作写入审计日志，但日志不记录完整密钥。

## 5. 数据模型

`User` 继续作为任务归属主体，但身份字段改为：

- `accessKeyHash`：密钥 SHA-256 哈希，唯一。
- `keyPrefix`：用于管理员列表的安全显示前缀。
- `keySuffix`：用于管理员列表的末四位。
- `note`：管理员备注，可空。
- `lastUsedAt`：最近一次成功密钥登录时间，可空。
- `enabled`、`studioId`、任务关系和时间字段继续保留。

旧的 `username`、`normalizedUsername` 和 `passwordHash` 字段移除。迁移时已有用户和历史任务保留，旧身份转换为不可登录的停用记录；管理员新建密钥后使用新的密钥身份。

## 6. API 设计

### 6.1 用户认证

- `POST /api/v1/auth/user/key-login`
  - 输入：`{ key }`
  - 成功：创建用户会话并更新 `lastUsedAt`。
  - 失败：统一返回“密钥无效或已停用”，不泄露密钥是否存在。
- 用户会话查询和退出接口路径保持不变。
- 删除用户注册和账号密码登录的前端入口；旧接口不再由前端调用。

### 6.2 管理员密钥管理

- `POST /api/v1/admin/user-keys`
  - 输入：`{ note? }`
  - 输出：用户记录和只返回一次的完整密钥。
- `GET /api/v1/admin/users`
  - 返回掩码密钥、备注、状态、时间和任务数量。
  - `search` 同时匹配备注、前缀和末四位。
- `PATCH /api/v1/admin/users/:id`
  - 继续用于启用或停用。
  - 停用时撤销该用户全部会话。

## 7. 前端调整

### 用户端

- 登录页标题和说明改为密钥登录。
- 仅保留密钥输入框，支持粘贴并自动去除首尾空格。
- 工作台顶部显示备注；无备注时显示 `密钥用户 · 尾号 XXXX`。

### 管理员端

- 导航和页面标题改为“密钥管理”。
- 增加创建密钥对话框和创建结果对话框。
- 完整密钥使用等宽字体展示，支持一键复制。
- 管理员任务列表中的提交用户改为备注或掩码密钥标识。
- 工作室设置中移除用户注册链接的显示和轮换入口。

### 工作室端

- “提交用户”显示备注或掩码密钥标识，其他队列交互保持不变。

## 8. 错误处理

- 密钥缺失或格式不合法：前端即时提示，服务端返回 400。
- 密钥不存在或已停用：统一返回 401，不区分具体原因。
- 创建密钥失败：不在前端展示未确认持久化的密钥。
- 复制失败：保留完整密钥对话框并提示手动复制。
- 并发停用或启用继续使用服务端最终状态响应刷新列表。

## 9. 测试与验收

- 管理员可创建带备注和无备注的密钥。
- 完整密钥仅创建响应出现一次，数据库和列表不包含原文。
- 正确密钥可登录，错误密钥和停用密钥不可登录。
- 停用后现有会话立即失效，重新启用后同一密钥可再次登录。
- 用户提交任务后，用户端、工作室端和管理员端均显示相同的备注或密钥标识。
- 自动化测试使用独立 `studio_tasks_test` 数据库，不影响开发密钥和任务。
- 桌面和手机宽度下，登录、创建密钥、复制和停用流程可完整操作。
